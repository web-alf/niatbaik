# Yatimpia Laravel Rewrite — Design Spec

**Date:** 2026-05-19
**Status:** Approved
**Scope:** Full rewrite of yatimpiatu.com from CodeIgniter 3 to Laravel

---

## 1. Context

Yatimpia is an Islamic crowdfunding/donation platform (yatimpiatu.com) currently built on CodeIgniter 3 (EOL). The codebase has 10 critical security vulnerabilities including plain text passwords, SQL injection across all queries, disabled CSRF/XSS protection, and local file inclusion. Architecture is fragmented with two parallel DB connection systems (CI Active Record + raw PDO in `server/` folders).

## 2. Decisions

| Aspect | Decision |
|---|---|
| Framework | Laravel (latest) + Blade + Livewire |
| Docker | Laravel Sail (PHP 8.3, MySQL 8.0, Redis, Mailpit) |
| Migration approach | Big Bang Rewrite |
| Auth | Laravel Breeze, 3 roles: user, fundraiser, admin |
| Payment gateway | Retain iPaymu + cekmutasi, wrapped in PaymentService |
| Database | Migrate legacy data, redesigned schema, 19 new tables |
| Legacy passwords | Force reset all existing users (plain text not re-hashed as-is) |
| Frontend | Tailwind CSS + Alpine.js + Vite |
| DataTables | Livewire component replaces raw PDO `server/` endpoints |
| Quran data | Static JSON files, removed from DB |

## 4. Database Schema

Migration from 33 CI3 tables/views to 19 normalized Laravel tables:

| CI3 (Old) | Laravel (New) | Changes |
|---|---|---|
| `user` (plain text pw) | `users` | bcrypt password, timestamps, soft deletes |
| `invoice` + `invoice_table` + `invoice_view` + `invoice_donatur` | `donations` + `invoices` | Separate donation & invoice. Drop DB views, use Eloquent scopes |
| `project` + `project_view` + `project_money` | `campaigns` + `campaign_funds` | Clearer naming, proper foreign keys |
| `project_info` + `project_info_view` | `campaign_updates` | Campaign update posts |
| `project_fundraiser` + views + clicks | `fundraisers` + `fundraiser_clicks` | Fundraiser tracking |
| `bank` + `bank_payment` | `bank_accounts` + `payment_methods` | Separate user bank & payment methods |
| `page` (type=blog/page) | `posts` + `pages` | Separate entities instead of type flag |
| `category` | `categories` | Add slug |
| `slide` | `slides` | Same |
| `settings` + `master` | `settings` | Merged key-value store |
| `history_komisi` + `history_withdraw` | `commissions` + `withdrawals` | Clearer naming |
| `money_management` | `financial_reports` | — |
| `quran` + `quran_surah` | Removed | Static JSON files in storage/ |
| `z_provinsi` | `provinces` | — |

## 7. Security — All 10 Issues Resolved

| # | CI3 Issue | Laravel Solution |
|---|---|---|
| 1 | Plain text password | `Hash::make()` / `Hash::check()` — bcrypt |
| 2 | SQL Injection | Eloquent ORM + query builder, zero raw interpolation |
| 3 | CSRF off | `@csrf` in all forms, automatic middleware |
| 4 | XSS off | Blade `{{ }}` auto-escapes output |
| 5 | LFI via dynamic view | Explicit routes, no user-controlled view paths |
| 6 | Empty encryption key | `APP_KEY` via `php artisan key:generate` |
| 7 | Session save path NULL | Redis session driver |
| 8 | CORS wildcard | `config/cors.php` with specific origins |
| 9 | Fake ssl()/de_ssl() | Removed. `Crypt::encrypt()` if needed |
| 10 | Unvalidated base64 $_GET | Route model binding, no encoding |

**Additional security (free with Laravel):**
- Rate limiting on login
- Email verification
- Password confirmation for sensitive actions
- Secure cookies (httponly, samesite, secure)
- Form Request validation on every endpoint
- Mass assignment protection via $fillable

## 9. Data Migration

**Command:** `php artisan migrate:legacy`

**Execution order:**
1. categories ← category
2. provinces ← z_provinsi
3. settings ← settings + master
4. users ← user (hash passwords, set force_password_reset)
5. campaigns ← project
6. campaign_updates ← project_info
7. campaign_funds ← project_money
8. bank_accounts ← bank
9. payment_methods ← bank_payment
10. invoices ← invoice
11. donations ← invoice_donatur + data_donatur
12. fundraisers ← project_fundraiser
13. fundraiser_clicks ← project_fundraiser_click
14. commissions ← history_komisi
15. withdrawals ← history_withdraw
16. posts ← page WHERE type='blog'
17. pages ← page WHERE type='page'
18. slides ← slide
19. financial_reports ← money_management

**Password strategy:** All legacy users get random temporary password + `force_password_reset = true`. On login attempt, redirect to reset flow with email verification. Plain text passwords are NOT re-hashed as-is (already exposed).
